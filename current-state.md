_**Standing rule added 2026-09-21 (`HL-0031`), bought by Rachel's own error.** Archive-then-recreate takes the file content **inline**, which invites composing new text straight into the write. **Never do it.** Edit the file, read it back, write exactly what was read — on a Drive write exactly as on an email (`RA-32`). A composed write **cannot be byte-verified**, because there is no source left to verify it against, and the check silently becomes a no-op. On 2026-09-21 that produced a Drive copy of **31,432 bytes** — above the `HL-0005` ceiling — that did not match the mirror. It was intact when read back, but that was luck, not control. **It then happened a second time the same morning, on the write that added this very paragraph** — which is why the rule now says the danger is highest when assembling a long write from read fragments, because that is when “just one more sentence” feels free._
